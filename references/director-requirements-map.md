# Director requirements, existing authorities, and compatibility boundaries

This is the architecture and traceability portion of [Director baseline audit #23](https://github.com/CompleteTech-Skills/hatch-pet/issues/23). It describes the code at **`7b966a639bcaf23bd3a0d037f46f29e2edfcc273`**, the default-branch revision inspected on 2026-10-22. It does not implement or approve the Director, its contracts, or its production demonstrations.

The authoritative requirements are [mission #18](https://github.com/CompleteTech-Skills/hatch-pet/issues/18), its [continuation covering sections 31–40](https://github.com/CompleteTech-Skills/hatch-pet/issues/18#issuecomment-6333798260), and its [phased delivery and mandatory interface addendum](https://github.com/CompleteTech-Skills/hatch-pet/issues/18#issuecomment-6333798568). Existing behavior is grounded in [README.md](../README.md), [SKILL.md](../SKILL.md), the source links below, and the associated regression tests. Test links identify relevant coverage; they do **not** mean that a new Director interface or a live integration has passed. The [companion baseline audit](director-baseline.md#actual-local-validation) records executed commands and their results separately.

Classification used below:

- **Reuse:** an existing implementation owns the stated narrower operation.
- **Extend:** preserve that owner and add a versioned adapter or additional supported behavior.
- **New:** the Director-specific component or contract is absent at the audited revision.
- **Capability gap:** execution depends on unavailable or unverified functionality, assets, tools, authorization, or provider configuration. A schema, discovery result, or fixture does not close this gap.

Issue numbers in the work columns are future implementation boundaries, not claims on those issues. Refresh GitHub and the default branch before starting them.
