# Exact physics clocks (#169)

This is a local stack on #168 (60acf5c); public #167 PR208 is pending. It does not claim those dependencies merged.

`fixed_step/substeps` is the requested solver interval, represented as a reduced rational. `fps` is the independent output sampling rate. Frame `n` occurs at `n/fps`; the half-open output range excludes its end frame. PyBullet3.2.7 runs full fixed steps to the ceiling of the final timestamp, then samples completed states using linear translation and shortest-arc quaternion slerp. `timing.json` records every exact timestamp, lower/upper solver index and alpha. These poses are explicitly labeled interpolated or directly solved. No shortened final solver step is introduced. Contacts are actual manifolds at the upper solver bracket; they are never interpolated.

Blender4.5.3 exposes integral `substeps_per_frame`. Incompatible requests fail admission. For NTSC30000/1001, for example, `fixed_step=1001/240000` yields eight native substeps per output frame. The worker reads native fps/substeps/iterations back and rejects changed or clamped settings. Blender arbitrary independent solver clocks remain unsupported. Animation evaluation follows exact output time. PyBullet caches every native solver step separately from output poses. Blender retains its embedded native point cache plus output samples; native substep extraction is unsupported. Rendering may independently seek verified completed samples through `inspect_time(cache, Fraction(...))`. Extrapolation beyond the last completed output is rejected.

The strict optional `solver.stability` object supports PyBullet `contact_penetration_tolerance` mapped to `contactSlop`, and `max_linear_velocity` / `max_angular_velocity` as observed-state failure limits at each solver step. Limits never clamp motion. Blender rejects these requests. Explicit CCD, sleeping thresholds and separate constraint iterations are rejected by both adapters pending verified implementation. Collision margins retain #168's explicit unsupported nonzero-skin policy. Existing iterations, damping, primitive validation and resource budgets remain in force.

Replay classification is hash-verified saved-state replay. Reruns remain not-guaranteed by default. A pinned-environment comparison only establishes numerical reproduction for its tested backend/version/executable/module/settings, seeds, hardware and tolerances. Seeds identify inputs; this rigid-body adapter uses no stochastic parameter. Native parallelism is the backend default; no cross-platform or bitwise simulation guarantee is made. Existing #168 caches remain readable with their original evidence; newly emitted caches require the timing receipt.

`tests/test_physics_timing.py` tests rational NTSC boundaries, terminal brackets, quaternion antipodes, unsupported controls and real solver oracles. Native checks require the same explicit environment and exclusive managed-process slot as #168. The real PyBullet oracle compares six early free-fall samples to the semi-implicit Euler solution within 1e-9m and continuous free fall within .004m; paired runs compare complete output values only in the pinned tested environment. Blender's continuous free-fall tolerance is .03m. These numerical checks do not establish artistic visual approval.
